# PM Review (s-1055): Full-Page Audit of Open-Kanban Frontend

> **Scope:** `frontend/src/` — 16 pages, 22 key components, core files (`App.tsx`, `main.tsx`, `styles/`).
> **Method:** Static code audit (Chrome DevTools MCP is not configured in this environment; only the kanban MCP is available, so a Playwright/Chrome session was not possible).
> **Reviewer perspective:** Senior Product Manager (UX, growth, reliability, accessibility, dark-mode, permission visibility).
> **Snapshot date:** 2026-09-17 (current `main` HEAD at `6a228ed`).

---

## 1. Headline

Open-Kanban's frontend has reached a state where **the product is functionally complete and the visual language is mostly coherent**, but the codebase has accumulated a large set of **copy-paste drift** issues that all share the same root cause: long, hand-typed Tailwind class strings that no linter ever validated. A single one-line **dark-mode class lint** (custom or via Stylelint) would have prevented the majority of the issues below.

**Headline numbers**

| Severity | Count |
|---|---|
| P0 (ship-blocker) | 9 |
| P1 (should-fix) | 28 |
| P2 (polish) | 34 |
| **Total** | **71** |

**Top three ROI fixes (each resolves 4–22 instances of the same root cause):**

1. Extract a shared `<Modal>`/`<Card>` class-string helper → fixes 21 modal + 22 card duplicates in one go.
2. Extract a shared `<Toast>` component → fixes 4 inconsistent toast implementations.
3. Centralize `darkMode` in `useUIStore` (drop the BoardPage/HeaderRightMenu parallel state) → fixes 2 theme-flicker bugs.

---

## 2. High-frequency root causes (the "why" behind the long list)

1. **Duplicated `dark:bg-zinc-700` followed by `dark:bg-zinc-800` on the same node** (21 modal/dialog locations). The two `dark:` declarations overwrite each other; the *last* wins, so the modal renders as `bg-zinc-800` in dark mode and the first `dark:bg-zinc-700` is dead code.
2. **Hover-card class with two `dark:hover:bg-zinc-*` declarations** (22 locations). The final `dark:hover:bg-zinc-700` overrides the earlier `dark:hover:bg-zinc-600`, so the hover state becomes *lighter* than the base — buttons "highlight downward" on hover in dark mode.
3. **Hard-coded `localStorage.removeItem('token')` in 5 places** — the logout contract is duplicated and never calls the server.
4. **Two independent dark-mode sources** (`main.tsx` synchronous class write + `BoardPage` local state + `SettingsPage` `useUIStore`) — theme can desync on navigation.
5. **Toast UI duplicated in 4 pages** with different class strings (one is dark-mode-safe, three are not).

## 3. P0 — Ship-blockers (9)

### P0-1 — Dead file: `HomePage.tsx` is never imported
- **File:** `frontend/src/pages/HomePage.tsx`
- **Description:** 193 lines, never referenced by `App.tsx`, `components/index.ts`, or anywhere else under `src/`. Includes a `handleLogin` flow that duplicates `LoginPage` and an unreachable `return <LoadingScreen />` at line 192.
- **Fix:** Delete the file.

### P0-2 — `HomeRedirect` redirects on data before setup is required
- **File:** `frontend/src/App.tsx` lines 28–45
- **Description:** `authApi.me()` race: when the user navigates directly to a non-`/` route, the redirect logic checks `data.needsSetup` / `data.user` before the spinner shows, and `useSetupGuard` on the destination page then double-bounces.
- **Fix:** Show `<LoadingScreen />` until `authApi.me()` resolves, not just when `cancelled`.

### P0-3 — `BoardPage` `darkMode` state ignores `localStorage` on remount
- **File:** `frontend/src/pages/BoardPage.tsx` lines 40–43, 123–130
- **Description:** Three independent dark-mode paths (`main.tsx` + `BoardPage` + `HeaderRightMenu`) overwrite each other. Toggling in one place doesn't update the others — UI flickers on navigation.
- **Fix:** Centralize on `useUIStore` (already used by `SettingsPage`).

### P0-4 — `ActivityTicker` blocks bottom-of-screen content permanently
- **File:** `frontend/src/components/ActivityTicker.tsx` lines 66–105
- **Description:** `fixed bottom-0 left-0 right-0 z-40` full-width ticker overlaps every page's footer/back-link/buttons. The `if (activities.length === 0) return null` early-return means once activities are fetched it never unmounts. On `BoardsPage` the GitHub footer at `fixed bottom-4 right-6` is hidden behind it.
- **Fix:** Move to top, give a max-height with overflow, or remove from layout entirely.

### P0-5 — `LoginPage` OAuth `handleProviderClick` redirects to `''` when `buildAuthorizeURL` returns empty
- **File:** `frontend/src/pages/LoginPage.tsx` line 217
- **Description:** `window.location.href = url` with `url === ''` navigates to relative root, silently sending the user to `/` and breaking the OAuth bounce-back contract.
- **Fix:** `if (!url) return;` *before* `window.location.href`, and surface the error in the `providersError` slot.

### P0-6 — `BatchOperationBar` clear-selection button uses light-bg on hover even in dark mode
- **File:** `frontend/src/components/BatchOperationBar.tsx` line 86
- **Description:** `hover:bg-zinc-50` (light zinc) is **not** qualified with `dark:`, so in dark mode the button briefly flashes light grey while text stays white → unreadable.
- **Fix:** Drop `hover:bg-zinc-50`; use `dark:hover:bg-zinc-600` only.

### P0-7 — `ColumnsPage` `setSelectedBoard` refetches without clearing `columns`
- **File:** `frontend/src/pages/ColumnsPage.tsx` lines 78–103
- **Description:** When the user picks a different board in the dropdown, the previous board's columns stay visible for one tick under the new header. The `loading` guard only triggers after the new fetch begins.
- **Fix:** Clear `columns` immediately when `selectedBoard.id` changes, before kicking off the new fetch.

### P0-8 — Duplicate `darkMode` reconciliation in `BoardPage` causes flicker on navigation
- **File:** `frontend/src/pages/BoardPage.tsx` lines 40–43, 123–130, 487–492
- **Description:** Same root cause as P0-3 — pick one source of truth.
- **Fix:** Use `useUIStore` exclusively.

### P0-9 — `localStorage.removeItem('token')` is hardcoded in 5 places; no server logout
- **Files:** `HomePage.tsx:100,181`, `BoardPage.tsx:342`, `SettingsPage.tsx:228`, `HeaderRightMenu.tsx:101`
- **Description:** Logout is implemented as `localStorage.removeItem('token') + navigate('/login')`. If the auth storage key ever changes, half the logout buttons will leave a stale token. There is no `authApi.logout()` server call, so the JWT remains valid server-side until expiry.
- **Fix:** Single `logout()` helper in `services/api.ts` (call server, clear localStorage, navigate). Replace all 5 call-sites.
