  and have the handler write **only** the raw enum, leaving the
  display layer to localise. 30-line diff across both locales +

### P1-5. `/api/v1/runs/history` rows still leak raw ANSI escape sequences into the `error` field

## P2 — Nice to Have / Polish

### P2-1. `/api/v1/templates` returns the literal string `null` instead of `[]` for admins

- File: `backend/internal/handlers/templates.go` (or whichever
  handler backs the route).
- Reproduced:
  ```
  $ curl -b "kanban-token=…" http://localhost:8080/api/v1/templates
  null
  ```
  The frontend's `templatesApi.getAll()` does `setTemplates(data ?? [])`
  so the UI is fine, but a `curl` user sees a literal `null`
  in their pipeline. CLAUDE.md says "Prefer returning empty
  arrays `[]` over `null` for list responses".
- Fix: replace `c.JSON(http.StatusOK, gin.H{"templates": nil})`
  with `gin.H{"templates": []models.Template{}}`. 2-line diff
  + handler unit test.

- Reproduced: `curl -b "kanban-token=…" http://localhost:8080/api/v1/archived`
  returns `null` until the admin archives something.
  (The `/completed` SPA page reads the same endpoint and
  already renders the empty state correctly, but again,
  a `curl` user sees a literal `null`.)
- Fix: same shape as P2-1. 1-line diff.

### P2-3. The `/api/v1/comments` and `/api/v1/subtasks` endpoints are *not* nested under `/api/v1/tasks/:id/comments` — surprising for a REST-shaped API

- File: `backend/cmd/server/main.go` (route registration).
- Reproduced on the live build:
  ```
  $ curl -X POST http://localhost:8080/api/v1/tasks/T-1002/comments \
         -H "Authorization: Bearer $TOKEN" -d '{"content":"x"}'
  {"error":"Not found"}
  $ curl -X POST http://localhost:8080/api/v1/comments \
         -H "Authorization: Bearer $TOKEN" \
         -d '{"content":"x","taskId":"T-1002"}'
  {"id":"…","content":"x","taskId":"T-1002",…}
  ```
  The flat `/api/v1/{comments,subtasks}` shape was probably
  chosen so the auth middleware can be reused, but it
  surprises anyone reading the OpenAPI spec who expects
  nested resources.
- Fix: either accept both shapes via a tiny alias, or
  document the flat shape prominently in `docs/API.md`.
  1-line middleware alias or 30-line docs section.

### P2-4. `POST /api/v1/tasks` creates the task with `published: false` (i.e. as a *draft*) by default

- File: `backend/internal/handlers/tasks.go` (the `CreateTask`
  handler).
- Reproduced:
  ```
  $ curl -X POST http://localhost:8080/api/v1/tasks \
         -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
         -d '{"title":"PM Review s-1258 smoke test",
              "columnId":"06cc35cb232300aad72a7f42a9fa4730",
              "priority":"high"}'
  {"id":"T-1002","published":false, …}
  $ curl http://localhost:8080/api/v1/columns?boardId=… | jq '.[0].tasks | length'
  0
  $ curl http://localhost:8080/api/v1/drafts | jq length
  1
  ```
  An integrator who doesn't read the OpenAPI spec writes
  a task, expects it to appear on the board, and gets a
  draft instead. They have to call
  `POST /api/v1/tasks/:id/publish` to make it visible.
- Fix: accept an explicit `published: true` request body and
  default to `true` (preserving the previous behaviour of
  showing on the board). If the project wants the
  draft-by-default contract, document it loudly in the
  API doc + add a `kanban tasks publish` CLI command.
  1-line diff + docs update.

### P2-11. WebSocket silently fails (403) when the SPA is served from a port not in `ALLOWED_ORIGINS`

- File: `backend/internal/handlers/websocket.go` (the
  `CheckOrigin` body) + `backend/internal/handlers/origins.go`.
- Reproduced (this very walkthrough — when I first booted the
  release on port 8082 with the default `kanban.env`, the
  console logged 18 × `WebSocket connection to
  'ws://localhost:8082/ws' failed: 403 Forbidden` and the
  avatar dot stayed red with a "重连中 (第 2/10 次)" toast).
- The fix is environmental (operators must add their custom
  port to `ALLOWED_ORIGINS`), but the **failure mode** is
  terrible: the user gets no actionable hint, and the dev
  console is filled with 403s. The toast itself doesn't
  say *why*.
- Fix: enrich the toast text with
  "WebSocket 连接被服务器拒绝 (403)。请确认 ALLOWED_ORIGINS
  包含当前访问地址 `http://localhost:8082`，或联系管理员。",
  and add a one-shot `/api/v1/origins/check` endpoint the
  SPA can ping before connecting. 8-line diff.
