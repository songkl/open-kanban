# Senior PM 视角审视：Open-Kanban 全产品评审

> 评审对象：当前运行中的 Open-Kanban 主分支（含后端 Go + 前端 React 19）
> 评审方式：完整运行后端 + Web 端 → 走通核心路径 → 抓取 28 张关键页面截图（含登录、看板、列、设置、运行历史、活动、Agent、暗黑、移动端、创建任务、筛选等）→ 标注发现
> 评审者视角：高级产品经理（兼顾 UX、增长、稳定性、商业化）
> 数据快照：1 个看板 / 5 列 / 7 个任务 / 2 个用户 / 13 次任务运行 / 1 次评论 / 0 个 Webhook / 0 个模板

---

## 1. 总体结论（一句话）

Open-Kanban 已经是一个**功能完成度极高、AI-First 定位清晰**的自托管看板产品：**后端能力（多看板、OAuth 2.1、签名校验、Agent 接管、Webhook、Run History、活动日志）已远超"看板"本身**；但前端体验的**统一性、可发现性、移动端、无障碍、以及"任务运行闭环"的可视化**还有较大打磨空间，是当前最大的产品价值放大器。

**建议下一阶段（4–6 周）聚焦 3 件事：**
1. 把"任务运行（Task Run）"做成**看板的核心可视化对象**，让它从「隐藏在任务详情抽屉里」变成「列内卡片上的一等公民」。
2. 打通**全局导航 + 通知中心**（目前无统一侧栏，用户在子页面之间必须点"返回"，是最大的留存黑洞）。
3. 把**权限、Agent、模板、Webhook** 这些"高级功能"用一个引导式 Onboarding + 角色仪表盘暴露出来，让新用户 5 分钟内能跑通完整 AI 协作闭环。

## 2. 产品定位与差异化优势

### 2.1 定位验证
README + CHANGELOG 反复强调「**A collaborative kanban board built for the AI era**」「AI-First」「100% AI 写代码」。

✓ 这个差异化在当前 SaaS 看板赛道（Jira/Linear/Trello/Notion DB）里是**真实且稀缺**的：
- Linear 是「为开发者优化」但仍以人为主
- Trello/Notion 是「通用协作」
- **没有一个主流产品把"AI Agent 作为看板列拥有者 + Task Run 生命周期"做成产品核心**

### 2.2 已被实现的"AI-First"证据
从功能矩阵来看，差异化不仅停留在口号，已落地：

| AI-First 能力 | 落地点 | 状态 |
|---|---|---|
| MCP Server | `mcp-server/` + 一键 OAuth 2.1 接入 | ✓ 完整 |
| 列级 Agent Owner | `column_agents` 表 + 看板页"列归属 Agent"标识 | ✓ 完整 |
| 任务 Run 生命周期 | `task_runs` 表 + `/runs` 页 + claim/heartbeat/finish API | ✓ 完整 |
| 失败自动回收 | `runReaper` 后台 worker | ✓ 完整 |
| Webhook 出站 | `webhooks` + 事件总线 + retry | ✓ 完整 |
| Device Flow 鉴权 | `/oauth/device/*` | ✓ 完整 |
| 多 AI Runner 同抢一任务 | `/api/v1/runs/claim` | ✓ 完整 |

**结论：技术/后端的差异化是真的，PM 现在要做的是把这种差异化在 UI 上"显性化"。**

## 3. 用户体验深度评审（按页面）

> 所有截图均放在 `.opencode/skill-output/s-1188/`，可在评审会上直接投屏。

### 3.1 🟢 登录页（02-login.png）
**优点：**
- 极简、聚焦、零干扰
- "设置密码（可选）"对自托管场景很贴心

**问题：**
- 🔴 **没有语言切换** —— 全屏中文，国际化用户的第一个落差
- 🔴 **没有品牌 logo / slogan** —— 标题就是"Open kanban"四个字，过冷
- 🟡 没有"Forgot password?"链接（密码忘了只能重置数据库）
- 🟡 没有 OAuth 第三方登录按钮（虽然后端支持 OAuth 2.1 出站，但入站仅本地账号）

### 3.2 🟢 看板主页（13-board-default.png / 14-board-sys.png）

**优点：**
- 列宽稳定、视觉密度合理、状态色清晰
- 任务卡 ID（`#d-1007`）+ 优先级色点 + 评论/子任务计数 + 负责人头像 一目了然

**问题（PM 视角，重要）：**

1. 🔴 **"负责人"展示的是设备/Runner 名（`Mac-66681-9...`），不是真实人/Agent**
   - 从截图看：assignee 字段实际指向 `task_runs.runner`，但 UI 把它当"任务负责人"展示，导致用户**完全看不懂这张卡谁负责**。
   - 建议：拆成两个语义字段：① 真正被指派的人/Agent（`tasks.assignee_id`）② 最近一次执行的 Runner（"运行者"），用不同图标区分。

2. 🔴 **任务卡右侧的红色"A"圆标含义不清**
   - 截图里每一张卡都顶着一个 "A" 圆形头像（疑似当前用户=admin 的在线状态），但用户没有任何 onboarding 知道这是"我在线/已分配给我"。
   - 建议：要么隐藏，要么 tooltip 解释"这张卡提到了你/分配给你"。

3. 🔴 **状态徽章语言混乱**
   - 列名是中文（"待办/进行中/待测试/待审核/已完成"），状态枚举是英文（todo/in_progress/testing/review/done），筛选器又混用（"全部/中/高/低"）。
   - 用户要"心算翻译"。建议：所有可见文案统一跟随用户当前语言，状态枚举在 UI 上不裸露。

4. 🟡 **缺少列级别的批量操作**
   - 想"批量归档'已完成'列下所有卡"必须一一点开 → 移到"已完成管理"页才支持批量。
   - 建议：列头加 `⋯` 菜单："全部完成 / 全部归档 / 全部导出"。

5. 🟡 **没有泳道（Sprint / Epic / 时间轴视图）**
   - 后端有 `meta` JSON 字段可以扩展，但前端无任何视图。
   - Linear/Notion DB 都默认有"时间维度"，看板只暴露列维度是单薄的。

6. 🟡 **"搜索任务…"框无搜索维度提示**
   - 是全文搜索？只搜标题？也搜描述？用户不知道。
   - 建议：placeholder 改成"搜索标题、描述、评论…"并显示快捷键 `/`。

### 3.3 🔴 列详情页（25-column-detail.png）
**优点：** 有"负责人/发布者/列名/排序"4 维过滤 + 列名切换器
**问题：**
- **每个任务卡右下都有一个红"A"圆标**（与主页相同问题），但列详情页本应聚焦"该列任务的差异化视图"，却被同样的视觉噪音干扰。
- 缺少"卡片密度切换"（紧凑/标准/详细）—— 三种用户场景需要不同密度。

### 3.4 🟡 看板管理页（04-boards.png）
**优点：** 单卡就能进入/管理/编辑/复制/导出/删除/导入，操作密度合理
**问题：**
- 🔴 **只能展示 1 个看板，无搜索、无排序、无标签**
   - 当用户拥有 10+ 看板时，这个页面就废了。
   - 建议：加"按最近活跃/创建时间/任务数/所有者"排序 + 关键词搜索。
- 🟡 看板卡片上**只显示"创建时间"，不显示"最后活跃时间"**——后者对自托管用户更有价值（决定"哪些看板可以删"）。

### 3.5 🟢 列管理页（05-columns.png）
**优点：** 拖拽改顺序、彩色标识列、内置 5 个默认列
**问题：**
- 🟡 **没有列"工作流自动化"配置**（如"移到 X 列时自动通知 Agent Y"）
   - 后端 `column_agents` 表只支持"列归属"，不支持"列流转触发器"。
   - 这是把看板从"被 Agent 操作"升级到"Agent 间自动流转"的关键。

### 3.6 🟢 任务详情抽屉（22-task-detail.png）—— **本评审最关键的页面**

**优点：**
- 信息架构齐全：状态/时间/描述/Run/元信息/子任务/附件/评论 + 编辑/复制/全屏/关闭 + 归档/删除
- 评论框支持 Markdown
- 任务 Run 信息完整：Runner/Agent/开始/心跳/过期/结束/退出码/stderr

**🔴 严重问题：**

1. **状态徽章自相矛盾** —— 截图里同一行显示「**🤖 运行中   已完成**」（同时"运行中"+"已完成"）
   - 这要么是 stale state 没清，要么是 UI 渲染逻辑 bug，必须立刻修。
   - 这是 PM 必须要求"零容忍"的一类问题：状态显示是产品最基础的信任锚。

2. **Run 详情被埋在抽屉里，没进入列视图** —— Run 是这个产品最大的差异化资产，但用户在主屏看不到任何"任务正在被 Agent 执行"的视觉信号。
   - 建议：列内任务卡显示 spinner 进度条 + "Runner: MacMini · 5秒前" + 点击跳转 Run 流。

3. **"编辑任务"是模态框，但评论是抽屉右侧** —— 一个任务卡有 3 个入口（卡本身、抽屉、模态编辑），新人完全搞不清。
   - 建议：合并为"统一任务抽屉"，所有编辑在抽屉内完成。

### 3.7 🟡 设置中心（09-settings.png）
**优点：** 9 个分类齐全：个人信息 / Token / 活动 / Agent / 用户 / 快捷键 / OAuth / Webhook / 主题

**问题：**
- 🔴 **键盘快捷键页面没发现截图证据**（被跳过了），但菜单已声明有；如果实际是空的就是虚假承诺，要验证。
- 🔴 **没有"通知偏好"分类**（邮件/Webhook 触发条件），对自托管 + 团队协作是刚需。
- 🟡 **设置项没有权限隔离说明** —— 普通用户和 ADMIN 看到的菜单应该不一样（现在所有菜单对所有登录用户都可见，包括"用户管理"）。
- 🟡 **"主题"在菜单最后**，对 50% 偏好暗色的开发者来说应该一键可达（建议放右上角）。

### 3.8 🟢 活动日志（10-activities.png）
**优点：** 33 条记录、操作类型/起止时间多维过滤、操作人/IP/来源一目了然
**问题：**
- 🟡 **没有"按看板/列/任务范围"过滤** —— 当前是全局活动，日志一多就难以定位。
- 🟡 没有"导出活动"按钮（审计场景需要）。

### 3.9 🟢 Agent 活动（11-agent-activity.png）
**优点：** 区分 Agent 与人活动、按 Agent 过滤、自动刷新开关
**问题：**
- 🟡 当 Agent 数量 > 5 时，"最近活跃"列表会很挤；建议改用下拉/搜索。
- 🟡 没有"Agent 健康度"指标（最近一次心跳、过去 24h 失败率、累计运行数）—— 这是 Agent 管理员最关心的。

### 3.10 🟢 运行历史（12-runs.png）
**优点：** 时间/任务标题/Runner/状态/耗时/标准错误 6 列表格清晰
**问题：**
- 🔴 **截图里一半任务都"失败"**，stderr 显示 `opencode run [message..] run opencode with a message Positional: message message to send...`
   - 这是真实产品 bug：从 stderr 看，Agent 被启动但参数解析失败。需要在 PM 评审中标记为「必须解决」—— 一个 50% 失败率的核心功能等于不存在。
- 🟡 没有"重试 Run"按钮（既然有 stderr，重试是最自然的修复闭环）。

### 3.11 🟡 已完成 / 历史归档 / 草稿箱（08/06/07.png）
**优点：** 三个独立页面分别管"已完成/归档/草稿"，统一空态文案"暂无…任务"
**问题：**
- 🟡 **"已完成"页面无"查看归档"入口** —— 用户清空"已完成"列表后无法找回。
- 🟡 **历史归档页面有"活动日志"按钮**（截图看到），但逻辑上"活动日志"是审计维度，"归档"是任务维度，两个混在一个 tab 有点歧义。
- 🟡 三个空态页面都只有「暂无任务」一句话，**没有引导"创建第一个任务"或"导入模板"的 CTA**。

### 3.12 🟢 创建任务模态（15-create-task-modal.png）
**优点：** 必填项明确、Markdown 编辑预览切换、看板/列下拉、发布/草稿开关、优先级下拉
**问题：**
- 🟡 **没有"截止日期"字段** —— 后端 `tasks` 表有时间戳但无 due_date，前端也无控件。
- 🟡 **没有"指派人"字段** —— 模态里只能选看板/列/优先级，无法在创建时分配给 Agent 或人。
- 🟡 **没有"附件"字段** —— 附件只能事后在抽屉里加。

### 3.13 🟡 筛选器（16-filter-modal.png）
**问题：**
- 🔴 **只有 3 个筛选维度**（优先级/负责人/时间范围）—— 对一个有 13 次 Run、7 个任务、5 列的产品来说太单薄。
- 缺失：标签、Run 状态、是否有评论、是否有子任务、自定义 meta 字段。
- 🟡 筛选后没有"已应用 N 个筛选"的可视化，用户不知道当前生效的过滤条件。

### 3.14 🟡 移动端（20-mobile-board.png）
**优点：** 整体可读、没有明显错位
**问题：**
- 🔴 **列布局完全水平滚动**（5 列一次性塞进 375px），每列只有约 70px 宽，根本无法读卡。
   - 必须做**列横向滑动 + 当前列内卡片纵向堆叠**的切换；或者**底部 tab 切换列**。
- 🟡 顶部"搜索/筛选/创建"按钮被裁掉一半（屏幕 375 + 三按钮总宽 ≈ 600）。
- 🟡 用户头像、列头计数器在移动端都偏小。

### 3.15 🟢 暗黑模式（21-dark-board.png）
**优点：** 整体色温舒服，列头色块保留品牌识别度
**问题：**
- 🟡 **任务卡背景不够深**（仍偏白），对比度可再降 1 档。
- 🟡 任务卡上"中"优先级色块偏暗，不够跳。
- 🟡 红色"A"头像圆在暗背景下太刺眼。

## 5. 关键产品机会（按 ROI 排序）

### 5.1 🥇 把"Task Run"做成看板的视觉中心
**为什么：** 这是 Open-Kanban 与 Linear/Jira 最大的差异点，也是用户最愿意付费/分享的"哇时刻"。
**怎么做：**
1. 列内任务卡显示「正在运行」的 spinner + 进度条 + Runner 名称
2. 抽屉顶部常驻一个"运行时间线"组件（类似 CI 流水线的步骤条）
3. `/runs` 页改为"实时运行大屏"（WebSocket 推送 + 全屏模式）
4. Run 完成后自动弹通知（"✅ MacMini 在 35 秒内完成了'还有多天过年？'"）

### 5.2 🥈 全局导航 + 通知中心
**为什么：** 当前无侧栏，所有页面切换必须走"返回"按钮，导致用户感知不到产品功能的广度。
**怎么做：**
1. 左侧常驻 64px 图标侧栏：看板/搜索/Agent/活动/运行/设置
2. 顶部右侧加铃铛图标 + 未读红点
3. 通知类型：任务被分配 / Run 完成 / 评论 @你 / Webhook 失败

### 5.3 🥉 仪表盘页（Dashboard）
**为什么：** 后端 `/api/v1/dashboard/stats` 已有数据，前端**完全没调用**。
**怎么做：**
1. 首页重定向到 `/dashboard`（而非直接 `/boards`）
2. 展示：活跃看板数、过去 7 天完成任务数、Top 3 Agent 排行、阻塞时间最长的 3 张卡

### 5.4 4️⃣ Onboarding + 模板市场
**为什么：** 新用户登录后看到的是 0 任务的空白页，没有引导。
**怎么做：**
1. 首次登录引导：选 1 个预置模板 → 自动建看板 → 装 1 个示例 Agent → 触发 1 次 Run
2. 公开模板市场（自托管可禁用）："产品迭代 / Bug Triage / 内容日历 / 客户支持"

### 5.5 5️⃣ 标签 + 自定义字段
**为什么：** 后端 `meta` JSON 已支持任意 K-V，但前端没暴露。
**怎么做：**
- 列设置里加"自定义字段"，类型：文本/数字/日期/单选/多选
- 任务卡上展示为彩色 chip
- 筛选器按自定义字段过滤

## 6. 增长与商业化建议
