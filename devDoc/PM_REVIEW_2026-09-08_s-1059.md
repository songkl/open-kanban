## P0 — Ship Blockers

### P0-1. `t('column.manageColumns')` returns the literal key as a `title=` attribute
- Files: `frontend/src/components/BoardHeader.tsx:219`, `frontend/src/pages/BoardPage.tsx:454`
- DOM evidence (chrome-devtools `document.querySelectorAll('[title]')` on `/board/gbk`):
  ```
  A title="column.manageColumns" href="/columns?boardId=gbk"
  A title="agentActivity"       href="/agent-activity"
  ```
- Root cause: the `column.manageColumns` key does **not exist** in
  `frontend/src/i18n/locales/{en,zh}.json` (`grep -c manageColumns = 0`). The
  icon-only `Link` in `BoardHeader` therefore ships the unresolved i18n key
  to screen readers and hover tooltips, and the same key was copy-pasted into
  `BoardPage.tsx` for the second link.
- Fix: add `column.manageColumns` to both locale files (e.g. `zh: "管理列"`,
  `en: "Manage columns"`) and switch the calls to `t('column.manageColumns')`
  once the key exists, or simplify the call to `t('nav.columnManagement')` which
  already exists (zh.json:54, en.json:54) and is what the BoardsPage uses.

### P0-2. `t('agentActivity')` is missing the `nav.` namespace
- File: `frontend/src/pages/BoardPage.tsx:506`
- DOM evidence: `A title="agentActivity" href="/agent-activity"` (the page
  literally shows the key to assistive tech).
- Root cause: `frontend/src/i18n/locales/zh.json:64` defines
  `nav.agentActivity = "Agent 活动状态"`. The code calls `t('agentActivity')`
  with no namespace, so i18next returns the key as the fallback.
- Fix: change to `t('nav.agentActivity')`. Same one-line fix for any other
  `t('agentActivity')` call sites — `grep -n "t('agentActivity')" frontend/src/`
  returns only the BoardPage line.

### P0-3. `BoardCard` "Import" button uses hard-coded English text
- File: `frontend/src/components/BoardCard.tsx:143`
- The button label is the literal string `Import` while every neighbouring
  label (CSV, JSON, 编辑, 复制, 另存为模板, 导出) is `t('…')` resolved. The
  i18n key `board.importBoard` already exists at
  `frontend/src/i18n/locales/zh.json:369` ("导入看板").
- Fix: replace `Import` with `{t('board.importBoard')}` and add a matching
  `board.importButton` or reuse the same key for symmetry with the CSV / JSON
  buttons.

### P0-4. `ColumnCard` action buttons (权限 / 编辑 / 删除) completely disappear in dark mode
- File: `frontend/src/components/ColumnCard.tsx:88-108`
- Screenshot evidence: `s1059-25-columns-dark.png` — the right side of every
  column row is blank; hovering reveals three buttons but they are
  bright-on-dark (light violet / blue / red on the dark card) and the icons
  in particular fight the row's `bg-zinc-800` background.
- Root cause: the three buttons use only light variants
  (`bg-violet-50 text-violet-600`, `bg-blue-50 text-blue-600`,
  `bg-red-50 text-red-600`). The `opacity-0 group-hover:opacity-100` wrapper
  also means non-mouse users (keyboard, screen reader) cannot see the
  controls at all until they tab into them.
- Fix: add dark variants
  (`dark:bg-violet-900/30 dark:text-violet-300`, etc.) and either drop the
  `opacity-0` initial state on `prefers-reduced-motion` or replace the
  hover-only reveal with a permanently visible icon button at narrow widths.

### P0-5. `t('settings.activities.PERMISSION_GRANT')` (and other `PERMISSION_*` actions) leak the full key
- File: `frontend/src/pages/ActivityLogPage.tsx:299`,
  `frontend/src/components/settings/ActivitiesSettings.tsx:152`,
  `frontend/src/pages/AgentActivityPage.tsx:448`,
  `frontend/src/components/ActivityTicker.tsx:87-88`,
  `frontend/src/pages/UserDetailPage.tsx:116`
- DOM evidence (s1059-08, s1059-26):
  ```
  📌 settings.activities.PERMISSION_GRANT – 进行中
       user=7478b1e2906f0a04162c55431fc79041 access=WRITE
  ```
- Root cause: the code does
  `t('settings.activities.${activity.action}')` and the locale only defines
  the legacy actions in `frontend/src/i18n/locales/zh.json:577-596`. The new
  `PERMISSION_GRANT`, `PERMISSION_REVOKE`, `PERMISSION_BULK_GRANT`,
  `PERMISSION_TRANSFER` actions introduced by s-1008 / s-1025 have **no
  translation key**, so i18next falls back to the full key string.
- Fix: add the four `PERMISSION_*` keys to both locale files (zh: "授权" /
  "撤销授权" / "批量授权" / "转移所有权"; en: "Permission granted" /
  "Permission revoked" / "Bulk permission grant" / "Ownership transferred")
  and audit the rest of `t('settings.activities.${action}')` for any other
  action that the backend may emit (e.g. `BOARD_COPY`, `TEMPLATE_*` are
  already there but `LOGIN_FAIL`, `EXPORT`, `IMPORT` are not).

## P1 — Should Fix This Milestone

### P1-1. "动态注册当前true。" is poor Chinese and still uses the raw boolean
- File: `frontend/src/components/OAuthSettings.tsx:129`
- DOM evidence (s1059-10): `动态注册当前true。` — the `{{enabled}}` placeholder
  is filled with the JS `true` / `false` literal.
- Root cause: the i18n key in `frontend/src/i18n/locales/zh.json:802` reads
  `"动态注册当前{{enabled}}。"` (note the Chinese period at the end and the
  raw placeholder), and the English version at
  `frontend/src/i18n/locales/en.json:802` reads
  `"Dynamic registration is {{enabled}}."`.
- Fix:
  - Replace the strings with proper conditional forms, e.g.
    `t('oauth.admin.dynamicRegistration', { enabled: dynamicEnabled ? t('common.enabled') : t('common.disabled') })`
    and define `common.enabled` / `common.disabled` in both locales.
  - Or change the i18n string to `"动态注册：{{state}}。"` and pass the
    human string from the component.

### P1-2. The owner "crown" 👑 icon appears on every board the user owns, but there is no corresponding "Public" badge
- File: `frontend/src/components/BoardCard.tsx:39-62`
- Screenshot evidence: s1059-30-boards-light.png — the "gbk" board shows only
  the crown, the "default" board shows crown + 私有. The reverse side
  ("public boards" badge) is never rendered, so a user cannot tell at a
  glance which boards are discoverable by anonymous viewers.
- Fix: mirror the existing 私有 badge with a green "公开" badge gated on
  `board.isPublic === true`, and add `board.publicBadge` /
  `board.publicHint` keys to both locales.

### P1-3. The four `P1-1/P1-2` dark-mode findings from V1 (s-1055) are still present
- Re-confirmed visually on this session:
  - `frontend/src/components/BatchOperationBar.tsx:86` — `dark:hover:bg-zinc-7000` typo is still in the build (`s1059-04` light mode doesn't show the bar; s-1055 V1 grep evidence still applies).
  - `frontend/src/components/BoardCard.tsx:91-145` — the four action buttons
    (编辑 / 复制 / 另存为模板 / Import) still have only light variants. In
    dark mode (s1059-15) they render as bright pastel cards against the dark
    card body, which is the loudest element on the page.
  - `frontend/src/pages/BoardsPage.tsx:462` — the GitHub footer link still
    declares both `text-zinc-400 dark:text-zinc-400` and
    `dark:hover:text-zinc-300` twice; same goes for the "暂无看板" empty
    state icon (`text-zinc-400 dark:text-zinc-400`).
  - `frontend/src/components/ErrorToast.tsx:46-57` — `getTypeStyles` still
    has no `dark:` variants, so any toast that fires in dark mode is a
    bright white card.
- Fix: this is the same recommended single-PR from the V1 summary — fix the
  invalid `zinc-7000` token, collapse every `dark:bg-zinc-700 … dark:bg-zinc-800`
  pair to `dark:bg-zinc-800`, deduplicate the `dark:hover:bg-zinc-700` runs,
  and add dark variants for the four `BoardCard` action buttons plus
  `ErrorToast`. Estimated: ~30 files.

### P1-4. `BoardPage` shows the literal i18n key for the Agent-Activity link, and the page retry button still has no `onClick`
- Files: `frontend/src/pages/BoardPage.tsx:506` (already noted as P0-2) and
  `frontend/src/pages/BoardPage.tsx:354-356` (V1 P0-3, re-verified — the
  `<button>{t('app.error.retry')}</button>` is still missing its `onClick`
  handler. The user-reported "load failed" state therefore cannot recover
  without a full browser refresh.
- Fix: wire `onClick={() => window.location.reload()}` (consistent with how
  other pages handle the same state).

### P1-5. `setupGuard` / `HomeRedirect` still fire `authApi.me()` from at least four places on cold load
- File evidence (network panel for `/board/gbk`):
  ```
  GET /api/v1/auth/me  (×4)
  GET /api/v1/auth/me/column-access?boardId=gbk
  GET /api/v1/columns?boardId=gbk
  GET /api/v1/boards
  GET /api/v1/auth/me
  GET /api/v1/columns?boardId=gbk
  GET /api/v1/tasks/g-1001/attachments
  GET /api/v1/comments?taskId=g-1001
  GET /api/v1/auth/agents
  ```
- V1 P1-10 is still present. Centralize the auth probe in a Zustand store so
  the redirect happens once and is shared by `HomeRedirect`, `LoginPage`,
  `SetupPage`, and the per-page `useSetupGuard`.

### P1-6. "暂无任务 / 点击添加新任务" empty state has almost zero contrast in dark mode
- File: `frontend/src/components/Column.tsx` (via the columns rendered in
  s1059-16-board-dark.png)
- The placeholder text uses `text-zinc-500` with no explicit `dark:` variant,
  so against `bg-zinc-900` it sits well below WCAG AA contrast.
- Fix: add `dark:text-zinc-400` (or stronger) and surface a slightly larger
  CTA hint ("拖动或点击 + 新建") to make the empty state actionable.

### P1-7. Mobile `/boards` header buttons crowd the title
- Screenshot evidence: s1059-28-boards-mobile.png
- "列管理" + "新建看板" are forced onto the same row as the "看板管理" title
  and subtitle at ≤375 px width, which causes the title to wrap to two
  lines and the +button to lose its icon margin. The "Import" text under
  the board card is also fine; the cramped header is the issue.
- Fix: collapse "列管理" to an icon-only button below `sm:` and move the
  count under the title instead of beside it.

### P1-8. OAuth device page is reachable for non-admins but renders an empty form with no guidance
- File: `frontend/src/pages/OAuthDevicePage.tsx` (and the route it lives on,
  `/oauth/device`).
- Screenshot: s1059-20 — the page renders "用户码" + "批准" / "拒绝"
  buttons, but the buttons are disabled until the user types something. There
  is no explanation of where the user code comes from, no example, and no
  validation feedback. A non-admin user landing here from the bookmark has
  no idea what to do.
- Fix: add a one-line hint ("从你正在授权的设备或应用中输入一次性用户码"),
  client-side format validation (e.g. `XXXX-XXXX`), and a deeper link to
  the docs.

### P1-9. `SettingsPage` sidebar shows the OAuth 2.1 tab for every user
- File: `frontend/src/pages/SettingsPage.tsx:21, 195-201`
- The OAuth tab in the sidebar is admin-only by behaviour but is not gated
  by role. Non-admins who navigate to `/settings?tab=oauth` see an empty
  page with the "暂无注册的应用。" message and a useless "应用 / 已授权 / 设置"
  tabstrip.
- Fix: wrap the tab entry in `currentUser?.role === 'ADMIN' && …` (same
  pattern as `tokens`, `activities`, `agents`, `users`).

### P1-10. The "← 返回看板" / "← 返回" links use inconsistent copy
- Files: `frontend/src/pages/DraftsPage.tsx`, `frontend/src/pages/HistoryPage.tsx`,
  `frontend/src/pages/ActivityLogPage.tsx`, `frontend/src/pages/AgentActivityPage.tsx`,
  `frontend/src/pages/SettingsPage.tsx`
- The Drafts and History pages use "← 返回看板" while the activity log /
  settings / agent activity pages use the shorter "← 返回". On the
  SettingsPage it even renders as two text spans ("← " and "返回") in the
  snapshot.
- Fix: pick one phrase, add a single `common.back` (or `common.backToBoard`)
  key, and use it everywhere.

### P1-11. `SettingsPage` shows raw `admin` user-IDs in the user list
- Screenshot evidence: s1059-23
- The user rows show `kkk` and `admin` as expected, but the link `href`
  points to `/user/7478b1e2…` and `/user/e2ff49c0…`. The UUID is what
  gets copied to clipboard when the user uses the link; this is the right
  technical value but should be hidden in the UI in favour of the
  `nickname` plus an explicit "复制 ID" action.
- Fix: hide the ID inside a tooltip / "view details" link and let the
  nickname be the only visible identifier.

## P2 — Nice to Have / Polish

### P2-1. `/user/:userId` route does not exist in the published build
- File: `frontend/src/App.tsx:72` defines
  `<Route path="/user/:userId" element={<UserDetailPage />} />`, but
  visiting `http://localhost:8080/user/admin` redirects to
  `/settings?tab=users` (s1059-23). The user-detail page is therefore
  effectively unreachable from the UI.
- Fix: either expose a "View profile" link in the user list, or remove the
  page if it is intentionally hidden. Right now the routing mismatch is the
  worst kind of dead code — the route exists but the data flow does not.

### P2-2. The `agentActivity` key in zh.json at line 64 is duplicated at line 521
- `frontend/src/i18n/locales/zh.json:64` (`nav.agentActivity = "Agent 活动状态"`)
  and `frontend/src/i18n/locales/zh.json:521` (the `settings.agentActivity.*`
  object). Both files have the same duplicate. i18next silently picks one
  based on lookup order; future maintainers will be confused.
- Fix: pick a single canonical namespace and delete the other.

### P2-3. The activity-log filter dropdown uses the literal `全部` as the
"all" option on dark mode backgrounds
- Screenshot: s1059-26-activities-dark.png
- The select's `value="全部"` text becomes very low contrast against the
  dark surface. Same in the other dark-mode settings select fields.
- Fix: bump select text contrast in dark mode (`dark:text-zinc-100`) and
  confirm with axe / Lighthouse that the control's contrast ratio passes
  WCAG AA.

### P2-4. Board action buttons (权限 / 编辑 / 删除 / Import / CSV / JSON) have no
visible focus ring
- Across the entire `BoardCard.tsx` grid (`s1059-15`, `s1059-30`), none of
  the action buttons has `focus-visible:` styling, so keyboard users get no
  visual cue when they tab through them.
- Fix: add a `focus-visible:ring-2 focus-visible:ring-blue-500 focus-visible:ring-offset-1`
  rule once on the parent and inherit via a shared `.btn` class.

### P2-5. The GitHub footer link is `position: fixed` and overlaps the
"删除" trash button on narrow boards cards
- Screenshot: `s1059-30-boards-light.png` — the GitHub link is glued to the
  bottom-right and crowds the trash icon on the second board.
- Fix: render the footer inline at the bottom of the page rather than fixed,
  or hide it when a modal is open (V1 P2-11 still applies).

### P2-6. The `default` board shows a "👑" (owner) badge but the same
crown also appears on `gbk`
- Screenshot: s1059-30-boards-light.png
- This may be correct (the admin owns every board by default), but there
  is no tooltip or explanation, so the icon looks decorative. Add an
  aria-label that resolves to "你拥有这个看板" / "You own this board".

### P2-7. The OAuth device page buttons are labelled with Chinese + English
duplicates
- Screenshot: s1059-20 shows the heading "授权设备" and the buttons
  "批准" / "拒绝". These are fine, but the placeholder "用户码" should be
  `placeholder="XXXX-XXXX"` to show the expected format. (V1 P2-12 still
  applies.)

### P2-8. The BoardsPage header subtitle (`2 个看板`) is in the same row as the
title at all widths
- Files: `frontend/src/pages/BoardsPage.tsx:294-308`
- At 1440 px this is fine; at 375 px (s1059-28) the title gets pushed off
  the row. Add `flex-wrap` and let the count move to a new line on `sm:`.

### P2-9. The board-card icon (grid) and the activity-log "📌" emoji do not
have a dark-mode replacement
- The grid icon is fine in dark mode (uses `text-blue-600` which renders OK),
  but the activity-log emojis (🔑, 📝, 👤, 📋, 📌, 🤖) are color emoji and
  look out of place on the dark surface. Consider switching to inline SVGs.

### P2-10. The `agentActivity` test in `BoardActionsMenu.test.tsx` asserts
the i18n key appears in the DOM
- File: `frontend/src/components/BoardActionsMenu.test.tsx:60, 67`
- `expect(screen.getByText(/nav\.agentActivity/i)).toBeInTheDocument();`
  The test is locking in the broken behaviour (the i18n key leaking to the
  DOM). Update the assertion once the bug is fixed.
