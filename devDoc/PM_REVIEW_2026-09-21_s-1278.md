**Scope:** `frontend/src/components/TaskModal.tsx` (1,419 lines)

   (`1020` tests in `frontend`, all `go test ./...` in `backend`)

   `noAttachments` strings preserved for backward compatibility

| # | Section | Before | After | Impact |
|---|---------|--------|-------|--------|
| 1 | **Comments sidebar** when zero comments | empty white space (looked broken) | `💬 还没有评论 / 在底部输入第一条评论，开始协作` empty state with `data-testid="comments-empty-state"` | P1 — first impression, perceived broken modal |

| 4 | **Attachments empty state** | `<p>暂无附件</p>` | `📎` icon + label in dashed box (matches subtasks) | P2 — visual consistency |
| 5 | **Description empty state** | `<span>暂无描述</span>` smushed in prose | `📝` icon + "Click Edit to add a description (Markdown and images supported)" hint, only when `canEdit` is true | P1 — discoverability of the description feature |
| 6 | **Edit mode header** | no visual indicator that the user is editing | amber `✏️ 编辑中 / Editing` pill with `aria-live="polite"` and `data-testid="editing-badge"` | P1 — prevents accidental "I thought I was in view mode" saves |
| 7 | **Edit mode footer** | Save / Cancel as small links | Full keyboard hint `⌘ / Ctrl + Enter 保存` rendered with `<kbd>` chips + reordered so Save is on the right (Cancel now on the left) | P1 — power-user discoverability |

Each of the seven ships with a test case. The empty states use
`bg-zinc-50/50 dark:bg-zinc-900/30` + `border-dashed` so they read
as "intentionally empty" rather than "broken" on both light and dark
themes. Icons are emoji (no asset pipeline changes required) with
`aria-hidden` so screen readers skip them.

## Senior PM observations — *NOT shipped (logged for follow-up)*

These were flagged during the walkthrough but are out of scope for
the s-1278 commit. They follow the carryover pattern of the prior
PM reviews (s-1241, s-1243, s-1257, s-1258, s-1261, s-1263, s-1264).

### P2-1 — Edit-page ergonomics
- All edit fields (status / assignee / priority / due date / agent
  id / agent prompt) appear in a single 2-column block. Power users
  say the agent fields are "90 % noise"; collapsing them under an
  "Advanced" disclosure would make the modal feel lighter.
- No inline edit affordance for simple fields (priority, assignee).
  Currently the only way to change them is to enter the full edit
  mode, which scrolls them away from the title.

### P2-2 — Status pill should pick up column color
- Header status pill renders on `bg-zinc-100`, identical for every
  column. `ColumnCard.tsx:74` already reads `column.color` for the
  card, but `TaskModal` only gets `columnName?: string`. Extending
  the `columns?: { id, name }[]` prop (or adding a new
  `columnColor` prop) would let the pill show a colored dot + tinted
  text — same trick used by `ActivityTicker` badges.
- Quick fix would be 6 lines + an interface change + a Playwright
  assertion that the pill color matches the source `column.color`.

### P2-3 — Archive / Delete footer weight is reversed
- Archive (`onArchive`) is currently a small `text-orange-500`
  link, while Delete is `text-red-500`. From a PM angle, **Delete
  is the higher-stakes action** and should be the one visibly
  guarded. Two possible treatments:
  1. Reverse order: keep Delete to the right (where most eyes
     land) but in a `bg-red-500 text-white` button matching the
     modal-wide destructive convention.
  2. Demote Archive to a chevron menu ("…") so Delete is the only
     text link visible by default.

### P2-4 — Comments pagination is a 1/3-wide footer (no scroll spy)
- With > 10 comments, the `上一页 / 下一页` buttons are anchored
  at the bottom of the *scrollable* comments column rather than
  the bottom of the sidebar. A long-thumbing operator loses track
  of where they are; an "X / Y page · K comments total" toast on
  page change would help.

### P2-5 — No quick-add comment when in edit mode
- Today the comment editor is `MarkdownEditor` *only* in edit mode
  (so a power user editing the task can't drop a quick comment
  without a separate click cycle). Some operators keep the markdown
  editor in both modes, others gate it behind "save first". Worth a
  product call — currently the gating is hidden.

### P3-1 — Column-move shortcut on the badge
- A right-click on the column pill in the header should offer a
  context menu with the same destination-column options as the drag
  affordance. Today the only way to move without re-saving is the
  drag from the board, which is invisible once the modal is open.

### P3-2 — Run timeline should not freeze the heartbeat forever
- `RunInfoSection` polls `useTaskRun(...5s)` while the modal is
  open. With a task-runs row in `failed` status, the modal stays
  "live" until the user closes it. Fine for finished runs; for a
  operator working through 20 tasks, the constant re-renders show
  up in DevTools. A visibility API pause would be appreciated.

### P3-3 — Modal title becomes unreadable on very small screens
- At < 640 px the `flex-wrap` on the header triggers and the title
  shrinks below ~14px because the `text-xl` doesn't downgrade.
  Worth checking on a 360 × 640 mobile screenshot.

### P3-4 — Save without dirty-checking
- Hitting `Save` (or `Ctrl+Enter`) currently fires `onUpdate` even
  if nothing changed. Not catastrophic, but a future "last saved
  at …" stamp would make the cost transparent.

## What did *not* change (intentional)

- **RunInfo / RunTimeline** — already shipped with s-1193 / s-1190.
  Considered for improvement but the recent s-1258 → s-1269 cluster
  already tightened those (full-mode `whitespace-nowrap`, retry
  button, status pill consistency). Out of scope here.
- **Subtask checkbox rendering** — already accessible. The new
  progress bar now sits *above* the list and provides machine- and
  human-readable feedback in one go.
- **Save shortcut handler** — the actual key handler (line 292:
  `if (e.key === 'Enter' && isEditing)`) is unchanged. The new
  hint is a discoverability affordance; the shortcut already
  worked.
- **Markdown editor** — lazy-loaded via `Suspense`; not touched.
- **Comment attachment rendering** — hidden behind the per-comment
  filter; not touched.
