## P0 — Ship Blockers

### P0-1. Invalid Tailwind class silently breaks hover-border on the "Column Management" link
- File: `frontend/src/pages/BoardsPage.tsx:309`
- Class string contains the malformed token `hover:border-zinc-200:border-zinc-600` (colons between two class names with no space). Tailwind drops the whole declaration, so neither light nor dark mode gets a hover border on the Column Management link.
- Fix: replace with `hover:border-zinc-200 dark:hover:border-zinc-600`.

### P0-2. Invalid Tailwind class `dark:hover:bg-zinc-7000` in BatchOperationBar
- File: `frontend/src/components/BatchOperationBar.tsx:86`
- There is no zinc-7000 color. The class is silently dropped, so batch action buttons do not get a dark-mode hover background.
- Fix: change to `dark:hover:bg-zinc-700` (and remove the trailing duplicate `dark:bg-zinc-700` while you're there).

### P0-3. Retry button in `BoardPage` error screen is dead
- File: `frontend/src/pages/BoardPage.tsx:354-356`
- The button is rendered with text `t('app.error.retry')` but has no `onClick` handler. Users hitting the load-failed state cannot recover without a full reload.
- Fix: wire it to a `refetch()` / `window.location.reload()` callback (other pages already do `window.location.reload()` on reset — keep behavior consistent).

### P0-4. `dark:bg-zinc-700 p-… shadow dark:bg-zinc-800` modal/panel pattern duplicates the dark background
- Affected files (representative sample, grep found ~30 occurrences):

## P1 — Should Fix This Milestone

Repeated `dark:hover:bg-zinc-700` / `dark:bg-zinc-700` / `dark:text-zinc-300` duplicates in the same `className`:
- `frontend/src/components/TaskCard.tsx:180, 274` (more-actions and view-details buttons)
- `frontend/src/components/TaskModal.tsx:443, 452, 466` (copy id / fullscreen / close buttons)
- `frontend/src/components/settings/AgentsSettings.tsx:311`
- `frontend/src/components/settings/ProfileSettings.tsx:71`
- `frontend/src/components/FileUpload.tsx:218`
- `frontend/src/components/TaskList.tsx:93` (duplicate `dark:hover:bg-zinc-600/50` + `dark:hover:bg-zinc-700/30`)
- `frontend/src/components/Column.tsx:262` (same as above)
- `frontend/src/components/BoardSelector.tsx` (referenced via grep)
- `frontend/src/components/HeaderRightMenu.tsx:64, 74, 83, 93` — text-zinc-700 + dark:text-zinc-400 has no dark:bg hover context, hover only swaps to zinc-600 not zinc-700
- `frontend/src/pages/UserDetailPage.tsx:180, 191, 203, 215`
- `frontend/src/pages/ActivityLogPage.tsx:267, 290`
- `frontend/src/pages/BoardPage.tsx:452, 504` (link buttons)

- `frontend/src/pages/AgentActivityPage.tsx:356`
- `frontend/src/components/BoardHeader.tsx:173, 195, 218` (header icon buttons all share the same broken duplicate pattern)

These are evidence that the styling went through several rounds of copy-paste-edit; cleaning them up will shrink the compiled CSS noticeably and remove confusion.

### P1-2. `TaskCard` task-ID chip and meta use non-existent dark variant
- File: `frontend/src/components/TaskCard.tsx:161, 318, 324, 341, 363, 367`
- Repeated `text-zinc-400 dark:text-zinc-400` and `text-zinc-400 dark:text-zinc-500` — the dark variant is essentially the same color so meta text becomes unreadable in dark mode.
- Fix: pick `dark:text-zinc-500` consistently for secondary meta and reserve `dark:text-zinc-400` only for the lowest-priority labels.

### P1-3. `CompletedPage` priority badges have no dark variant at all
- File: `frontend/src/pages/CompletedPage.tsx:15-19`
- `priorityColors` only has light-mode classes (`bg-red-100 text-red-700`, etc.). Dark mode users see a bright badge on a dark card — high contrast and visually loud.
- Fix: add dark variants matching `TaskCard` (`bg-red-100 text-red-700 dark:bg-red-900/50 dark:text-red-400`).

### P1-4. `BoardCard` action buttons all lack dark variants
- File: `frontend/src/components/BoardCard.tsx:91, 100, 109, 120, 129, 138, 147`
- Buttons use `bg-amber-50 text-amber-600 border-amber-100` (edit), `bg-purple-50 text-purple-600`, etc. — no `dark:bg-amber-900/20` etc.
- Fix: add `dark:bg-*-900/20 dark:text-*-300 dark:border-*-800/40` for each colored button.

### P1-5. `BoardsPage` empty state, error state, and footer use mismatched text colors
- File: `frontend/src/pages/BoardsPage.tsx:462`
- Footer link: `text-zinc-400 dark:text-zinc-400 hover:text-zinc-600 dark:text-zinc-300 dark:hover:text-zinc-300` — duplicates `dark:text-zinc-400` and declares two different `dark:text-*` classes in one element, with the later winning.
- Empty state icons: `text-zinc-400 dark:text-zinc-400` is invisible against `bg-zinc-50 dark:bg-zinc-700`.
- Fix: collapse the duplicate utilities, pick a visible dark variant (`dark:text-zinc-500` for icons, `dark:text-zinc-300` for body text).

### P1-6. `ErrorToast` has no dark-mode styling at all
- File: `frontend/src/components/ErrorToast.tsx:46-57`
- `getTypeStyles` returns only light variants (`bg-red-50 border-red-200 text-red-800`). In dark mode the toast appears as a bright white card, very jarring against the dark UI.
- Fix: add `dark:bg-red-900/40 dark:border-red-800 dark:text-red-100` etc. for each variant.

### P1-7. Settings sidebar mixes `dark:hover:bg-zinc-600` and `dark:bg-zinc-700` in the inactive style
- File: `frontend/src/pages/SettingsPage.tsx:27-33`
- `sidebarTabClass` returns `'text-zinc-600 hover:bg-zinc-100 dark:text-zinc-300 dark:hover:bg-zinc-600 dark:bg-zinc-700'` — again `dark:bg-zinc-700` and `dark:hover:bg-zinc-600` conflict; the hover wins but the static `dark:bg-zinc-700` is dead code that confuses readers.
- Same pattern in `frontend/src/components/TaskCard.tsx:193, 211` for the inline "Move to column" submenu.

### P1-8. `OAuthDevicePage` shows the OAuth tab for every user, but the tab is admin-only behaviorally
- File: `frontend/src/pages/SettingsPage.tsx:21, 195-201`
- `ALL_TABS` includes `'oauth'` and the sidebar button is rendered unconditionally, yet the tab only makes sense for ADMINs. The tab also has no permission gate, so non-admins can navigate to it and see an empty / broken panel.
- Fix: wrap the tab button in `currentUser?.role === 'ADMIN' && …` (same pattern as `tokens`, `activities`, `agents`, `users`).

### P1-9. Login button never tells the user why their account is being rejected
- File: `frontend/src/pages/LoginPage.tsx:49-67`
- The server returns `data.requirePassword` to indicate the account exists but needs a password — the UI just shows `data.error` which is sometimes blank. A first-time user with a password-required account sees a generic "login failed" with no password field appearing.
- Fix: if `data.requirePassword` is true and the password field is not shown, force-show the password field and a hint like "This account requires a password".

### P1-10. `useSetupGuard` + duplicate `HomeRedirect` initial auth probe
- Files: `frontend/src/App.tsx:21-52`, `frontend/src/pages/HomePage.tsx`, `frontend/src/pages/LoginPage.tsx:15-25`, `frontend/src/pages/SetupPage.tsx:96-112`
- The app fires `authApi.me()` from at least four places at startup (HomeRedirect, LoginPage, SetupPage, every `useSetupGuard`-using page). On cold load the user sees a flash of the previous page before the redirect lands.
- Fix: centralize the auth probe in a Zustand store / React-Query so the redirect happens once and is shared.

### P1-11. Skeleton component uses the same broken `dark:bg-zinc-700` + `dark:bg-zinc-800` pattern
- File: `frontend/src/components/Skeleton.tsx:37`
- See P0-4.

## P2 — Nice to Have / Polish

### P2-1. Drag handles and meta indicators in `DraftsPage`/`TaskCard` are inconsistent in dark mode
- `DraftsPage.tsx:312-315` and `TaskCard.tsx:140-149` both draw three-dot drag handles but use slightly different sizes (`w-1.5 h-0.5` vs `w-1 h-0.5`). Visually inconsistent across pages.
- Recommendation: extract a `DragHandle` component and reuse it everywhere.

### P2-2. No empty-state CTA when boards exist but all are inaccessible
- `BoardsPage.tsx:369-389` differentiates "no boards at all" vs "no accessible boards" but the latter case still shows the "Create Board" button if the user has permission. Consider surfacing an explicit message about why boards are hidden (e.g., a tooltip on the lock icon).

### P2-3. `CompletedPage` toast is `bg-zinc-800` with no dark variant override
- `CompletedPage.tsx:272` (and the same pattern in `BoardsPage.tsx:455`, `ColumnsPage.tsx:543`, `BoardPage.tsx:601`)
- These toasts render in dark mode as `bg-zinc-800` on a `bg-zinc-900` page — readable, but the toast class lacks a `dark:bg-zinc-700` so any future theme tweak has to update ~5 files in lockstep. Consider extracting a shared `<Toast>` component.

### P2-4. `ImportModal` import-confirm toast is missing
- `BoardsPage.tsx:251-266` — `handleImportConflictConfirm` shows `t('toast.importFailed')` when there is no `pendingImportData`, but no error path when the server returns non-409 errors.
- Recommendation: surface the server's actual error message via `showErrorToast(err.message, 'error')` instead of a generic toast.

### P2-5. `TaskModal` "Send comment" button never disables the editor while sending
- `TaskModal.tsx:286-305`
- After clicking "Send", the optimistic comment is appended and the field cleared, but `handleAddComment` does not await `onAddComment`. If the parent fails, the optimistic comment is never rolled back.
- Fix: capture `await onAddComment(...)` and remove the optimistic entry on error.

### P2-6. Permission gating for the "Save as template" button is implicit
- `BoardsPage.tsx:175-177`, `BoardCard.tsx:107-115`
- The button is shown for every board card regardless of access. Users without ADMIN/WRITE on a board can still trigger the action and see a generic toast.
- Fix: hide the button when the user has no write access to that board.

### P2-7. `BatchOperationBar` is mounted only when `selectedTasks.size > 0`, but its close logic relies on a parent state callback
- `BoardPage.tsx:586-598` — the bar is always rendered when there are selections; clearing selection via the bar unmounts it, which means any open menus inside the bar close without an animation.
- Recommendation: render the bar in a transition wrapper.

### P2-8. Dark mode contrast on `SearchBar` input border
- `frontend/src/components/SearchBar.tsx` (via grep)
- Uses `border-zinc-300 dark:border-zinc-600` which is OK, but the focus ring uses `focus:ring-blue-400` without a dark variant — looks fine but in dark mode the ring blends with the input.
- Recommendation: add `dark:focus:ring-blue-500`.

### P2-9. `ActivityTicker` has no light/dark-aware icons
- `frontend/src/components/ActivityTicker.tsx` (via grep)
- All icons hard-code `text-zinc-500` with no dark variant.
- Recommendation: add `dark:text-zinc-400`.

### P2-10. Mobile responsive layout for `BoardsPage` header
- `BoardsPage.tsx:294-328` — flex layout flips at `sm:` but the icon-only "Column Management" button (no text) is not resized for mobile; on narrow screens the right-side buttons wrap below the title awkwardly.
- Recommendation: hide icon button text on `sm:` screens via responsive utilities.

### P2-11. The footer GitHub link is fixed to the bottom of every page, which can overlap modal close buttons
- `BoardsPage.tsx:462-474` and similar in `SettingsPage.tsx`
- The `fixed bottom-4 right-6` placement means modals (e.g., `ImportModal`, `ImportConflictConfirm`) at the same z-index range can collide with the footer visually.
- Recommendation: hide the footer when any modal is open, or move it inside the page-level flow.

## Summary

| Severity | Count | Examples |
|----------|-------|----------|
| P0       | 4     | Broken Tailwind tokens, dead retry button, duplicate `dark:bg-*` on every modal |
| P1       | 11    | Duplicated `dark:hover:bg-zinc-700` everywhere, missing dark variants on `ErrorToast`, `CompletedPage` priorities, `BoardCard` action buttons, OAuth tab gate |
| P2       | 11    | Inconsistent drag handles, no toast abstraction, optimistic-comment rollback, mobile header overflow |

The most impactful single PR would be: **(1)** fix the two invalid Tailwind tokens, **(2)** collapse all `dark:bg-zinc-700 … dark:bg-zinc-800` pairs to `dark:bg-zinc-800`, **(3)** deduplicate the `dark:hover:bg-zinc-700` runs, and **(4)** wire the BoardPage retry button. Those four changes touch ~30 files but resolve the majority of P0/P1 styling issues at once.
